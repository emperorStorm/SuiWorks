# SuiWorks 纯静态架构与部署方案

> 方案 v1.0 · 2026-10-22 · 状态：工程已落地，待首次上线
>
> 目标环境：阿里云 ECS，2 vCPU / 1.8 GiB 内存 / 40 GiB 系统盘，Alibaba Cloud Linux 3。
>
> 正式 Vue SSG 工程、内容校验、浏览器测试、Nginx 模板和部署归档均已创建；当前不连接或修改服务器。

## 1. 结论

SuiWorks 当前是作品展示与下载索引站。作品列表、详情、分类筛选、关于页面和外部下载入口不需要服务端动态计算，采用纯静态站即可满足需求。

推荐方案：

| 层 | 选择 | 用途 |
| --- | --- | --- |
| 页面与路由 | Vue 3 + TypeScript | 作品首页、详情页、下载索引、关于页 |
| 构建与预渲染 | Vite + 静态站点生成（SSG） | 构建期生成 HTML、CSS、JS 与页面元数据 |
| 内容数据 | TypeScript 或 JSON 文件 | 作品资料随代码版本管理，构建时读取 |
| Web 服务 | Nginx | HTTPS、静态文件、缓存、安全响应头 |
| 下载与大文件 | GitHub Releases | 安装包不占 ECS 磁盘 |
| 发布 | 本机构建 + 部署归档 + 版本目录 | 服务器不安装 Node、不运行构建 |

当前不需要 Node API、Java 服务、MySQL、Redis、Docker、上传服务或 systemd 业务进程。Nginx 是唯一需要常驻的 SuiWorks 服务。

## 2. 需求与约束

- 原型已展示 6 件作品，包含作品卡片、形态筛选、详情抽屉、下载入口和关于区；作品数据集中在 `docs/prototype/assets/js/products.js`。
- 目标 ECS 为 2 vCPU、1.8 GiB 内存、40 GiB 系统盘；已用约 8.7 GiB，另有 4 GiB swap。
- 服务器当前未安装 Nginx、Node、Java、MySQL、Redis、Docker 或 Git。
- Qoder 远程运行时约占 830 MB；生产服务运行期间不应让该远程运行时常驻。
- 安装包和源码继续放在 GitHub Releases 或作品自身仓库，不上传到 ECS。

### 当前不做

- 在线内容管理后台、登录、用户账号与权限。
- 下载统计、留言、评论、站内搜索服务。
- API、数据库、缓存、服务端文件上传。
- 运行时 SSR、多机高可用、容器编排。

如果未来出现上述动态需求，再依据真实功能选择最小后端；不要提前安装数据库或缓存。

## 3. 架构图

```text
桌面浏览器 / 手机浏览器 / 平板
             │ HTTPS :443
             ▼
       阿里云安全组
       公网 22 / 80 / 443
             │
             ▼
          Nginx
      ┌──────┴────────┐
      │               │
      ▼               ▼
静态站点文件       GitHub Releases
HTML/CSS/JS/图片    安装包与源码
      │
      └── 浏览器本地筛选、路由与展示

本地内容文件 ── Vite SSG 构建 ── rsync 发布到 ECS
```

所有客户端访问同一套静态页面。移动端和桌面端的数据不是分别保存在服务器：页面内容由本地版本化数据构建而来，公开展示不需要按用户或设备读写数据。

### 请求路径

1. 浏览器通过 HTTPS 请求页面，Nginx 返回预渲染 HTML 和带内容哈希的静态资源。
2. Vue 在浏览器中完成交互、分类筛选和详情导航，不请求业务 API。
3. 图片作为静态资源由 Nginx 返回；点击下载时直接跳转到作品的 GitHub Releases 或仓库页面。
4. 修改作品内容后，在本机重新构建并发布新版本；不用重启应用进程或迁移数据库。

### 前后端边界

当前没有独立后端进程。前端页面、数据源和构建产物之间仍保持清晰边界，但无需为了形式上的前后端分离增加常驻 API。

## 4. 当前工程结构

```text
SuiWorks/

├── public/brand/              # 品牌与作品图标

```

原型归档继续保留在 `docs/prototype/`；正式站以 `content/works.ts` 为唯一作品数据源。构建期会校验 slug 唯一、必填字段、HTTPS 外链、颜色与本地图片是否存在。

## 5. 前端与页面生成

- Vue 3 + TypeScript + Vite；使用适配 Vue/Vite 的 SSG 方式生成首页、关于页和每个作品详情页。
- 已生成 `/`、`/about/`、六个 `/work/<slug>/` 目录页及 `/404.html`；Nginx 使用 `try_files $uri $uri/ =404`，详情刷新读取对应 `index.html`，缺失地址返回真实 HTTP 404，不回退首页。
- 分类筛选、菜单、详情预览等交互在浏览器本地完成；不为 6 件作品引入搜索服务。
- 作品资料保存在 `content/works.ts` 或 JSON，作为前端内容数据；不把用户私密信息、密钥或可变业务状态放入静态文件。
- 图片使用 WebP/AVIF 或优化后的 PNG/JPEG；懒加载非首屏图片，指定宽高以减少布局偏移。
- SSG 输出每页独立标题、描述、Open Graph 元数据，以及 `robots.txt`、`sitemap.xml`。
- 详情 URL 可直接打开、刷新和分享；继续兼容原型 `#product=<slug>` 深链接时，通过前端解析映射到正式详情路由。
- 字体使用系统字体，不依赖网络字体；首屏图片和 JS 体积作为构建验收项。

## 6. 静态资源与安全

### Nginx 职责

- 监听 80 并跳转 HTTPS；443 提供 TLS 1.2/1.3。
- 直接返回预渲染 HTML、JS、CSS、图片、图标与 SEO 文件。
- HTML 使用短缓存或不缓存；带内容哈希的 `/assets/` 长期缓存并标记 `immutable`。
- 开启 gzip；不需要 Brotli 模块或额外代理层。
- 设置 `X-Content-Type-Options: nosniff`、`Referrer-Policy` 等安全响应头；按正式资源清单配置 CSP。
- 关闭版本号暴露、限制访问日志保留期限。

### 不需要的安全面

静态站没有管理员会话、用户写接口、数据库端口、上传端点或 API 密钥，因此无需配置 CORS、会话 Cookie、API 限流和 SQL 权限。外部链接使用明确的 HTTPS 地址；不提供由用户参数控制的任意跳转。

## 7. 资源预算

以下为规划估算，实际部署后应以 ECS 监控数据校正。

### 内存

| 组件 | 常驻估算 | 说明 |
| --- | ---: | --- |
| 系统与云盾/监控 Agent | 200–280 MB | 基于现有服务器情况 |
| Nginx | 12–20 MB | 2 个 worker 的轻量静态服务 |
| SuiWorks 页面 | 0 MB 服务端常驻 | HTML、JS、CSS 由 Nginx 读取；浏览器承担交互 |
| **预计合计** | **约 0.21–0.30 GiB** | 不含 page cache 与临时构建进程 |
| **1.8 GiB 可用余量** | **约 1.5 GiB** | 供系统缓存、其他小型服务与峰值使用 |

Vite/Node 只在开发机或 CI 构建时使用，不作为生产常驻服务。Qoder 远程运行时约 830 MB，不应与生产栈长期并行。

### 磁盘

| 用途 | 规划 | 说明 |
| --- | ---: | --- |
| 系统与系统软件 | 11 GiB | 当前约已用 8.7 GiB，预留更新空间 |
| Nginx 与站点配置 | 0.5 GiB | 含证书、配置和日志空间 |
| 静态资源与最近 3 个版本 | 1 GiB | 实际取决于截图数量与尺寸 |
| 站点备份 | 1 GiB | 代码由 Git 保存；可备份部署产物与配置 |
| 日志与临时空间 | 1 GiB | 配置轮转与上限 |
| **规划占用** | **约 14.5 GiB** | 包含当前系统用量及上述预留 |
| **40 GiB 余量** | **约 25.5 GiB** | 可用于系统增长和其他项目 |

图片和安装包不要无限堆积在 ECS。安装包仍托管于 GitHub Releases；站点图片尽量纳入仓库或后续使用对象存储/CDN。备份应另存到 OSS 私有 Bucket 或另一台机器，不能只留在同一块系统盘。

### CPU 与带宽

- 对当前低频更新的展示站，2 vCPU 足够；静态页面无需应用服务计算。
- 首屏目标控制在 500 KB 左右，非首屏截图懒加载。
- 首版可直接由 Nginx 服务；访问量或跨地域速度有明确问题后再评估 CDN。

## 8. 部署与回滚

### 目录布局

```text
/opt/suiworks/
├── releases/
│   ├── 20261022-01/
│   │   ├── web/
│   │   ├── nginx/
│   │   ├── README.md
│   │   └── release.json
│   └── 20261022-02/
└── current -> releases/20261022-02

/etc/nginx/conf.d/suiworks.conf
/etc/nginx/snippets/suiworks-security-headers.conf
/etc/nginx/certs/<domain>/
```

仅在正式部署时创建这些服务器目录。证书私钥权限应限制为 root 与 Nginx 必要读取权限；私钥不进入仓库和发布包。

### 发布流程

```text
本机 npm run package:deploy
  → 类型检查、内容校验、SSG 与产物检查
  → 生成 artifacts/suiworks-<版本>.tar.gz
  → 上传并解包到 releases/<版本>
  → 原子切换 current 软链
  → HTTP/HTTPS 探活并抽查首页、详情与 404
```

常规静态版本切换无需 reload Nginx。只有首次安装或修改 Nginx 配置时，才执行 `nginx -t`，成功后 reload；回滚使用同样的原子软链切换。保留最近若干发布目录，清理前先核实当前软链与旧哈希资源依赖。

### 初次部署步骤

1. 确认域名、备案与 ECS 安全组；公网只开放 SSH 和网站所需的 80/443。
2. 创建 ECS 快照，安装 Nginx 与 rsync；不开通数据库、Redis、Node 或 Java 服务。
3. 配置 Nginx 站点、HTTPS 证书、静态目录、缓存头和安全响应头；`nginx -t` 通过后 reload。
4. 在本地或 CI 构建静态站，把产物发布到版本目录并检查正式域名。
5. 配置证书续期、日志轮转、云监控 HTTPS 探活和磁盘/内存告警。
6. 演练一次发布回滚，验证详情深链接、移动端布局、外部下载入口与 404 页面。

服务器目前没有被操作；以上是待实际部署时执行的步骤。

## 9. 备份、监控与维护

- 代码与作品内容：Git 仓库是主备份；保持远端仓库可用并避免把唯一副本留在 ECS。
- 服务器配置：备份 Nginx 站点配置、TLS 续期配置和必要的部署元数据；证书私钥用受控方式保管。
- 静态产物：可从指定 Git commit 重新构建；若构建不可复现，再额外归档当前发布包。
- 监控：使用阿里云云监控关注内存、CPU、磁盘、HTTPS 可用性和证书有效期；不安装 Prometheus/Grafana。
- 日志：Nginx access/error log 日轮转，设置总量和保留期；避免访问日志填满系统盘。
- 维护：更新 Nginx 与系统安全补丁；依赖更新在本机构建和检查后再发布。

## 10. 后续扩展边界

| 新需求 | 最小扩展方向 | 何时再引入 |
| --- | --- | --- |
| 在线编辑作品内容 | 轻量管理 API + 持久化存储 | 手工改内容文件已不方便时 |
| 跨设备用户数据同步 | API + 服务端数据库；客户端按需使用 SQLite/IndexedDB | 有真实账号和同步需求时 |
| 下载统计 | 下载重定向服务或第三方分析 | 统计数据会影响决策时 |
| 大量图片或全球访问 | OSS + CDN | ECS 带宽或图片维护成为瓶颈时 |
| 全文检索 | 先评估构建期索引/浏览器搜索 | 内容规模显著增长后 |

若未来增加服务端，先评估 Node + SQLite 或托管 API 是否足够；MySQL、Redis 不作为纯静态站的预装依赖。若需要多端数据同步且数据关系、事务和并发写入明确，再采用 MySQL 作为服务端数据源，各客户端通过 HTTPS API 访问，不直接连接数据库。
